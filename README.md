# PayGrade

A clickable, front-end-only UI prototype of a payroll system for **Mariveles Mental Wellness and General Hospital (MMWGH)**, a DOH-retained hospital in Mariveles, Bataan. It exists to validate workflows and screens with HR, Accounting, and management before full development.

There is no backend. All data is generated by a deterministic seed and held in zustand stores, persisted to the browser's `localStorage` so a demo survives page reloads. **Reset demo data** in the user menu restores the seed.

> Rates, tax tables, salary schedules, and holidays are **seed values for the prototype only**. Verify them against current GSIS, PhilHealth, HDMF, BIR, DBM, and CSC issuances before any production use. See [docs/assumptions-and-open-questions.md](docs/assumptions-and-open-questions.md).

## Setup

Requirements: Node.js 20.9 or later (tested on Node 24), pnpm 10 or later.

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

Other scripts:

```bash
pnpm test         # Vitest unit tests (payroll engine, seed, reports, loans, attendance)
pnpm lint         # ESLint
pnpm typecheck    # tsc --noEmit (TypeScript 7)
pnpm build        # production build
```

The demo "today" is **Sep 22, 2026**. Payroll is **monthly** (one period per calendar month, paid on the last day of the month). The current payroll period is **Sep 1 to 30, 2026**.

## Stack

Next.js 16 (App Router, Turbopack), React 19, TypeScript 7, Tailwind CSS 4, shadcn/ui on **Base UI** primitives, TanStack Table v9, react-hook-form with zod 4, date-fns 4, Recharts 3 through shadcn charts, zustand 5, sonner, decimal.js, Vitest.

TypeScript note: `typescript-eslint` does not yet support the TypeScript 7 API, so the project follows Microsoft's side-by-side setup. `@typescript/native` is TypeScript 7 (it provides `tsc`), and the `typescript` package name is aliased to `@typescript/typescript6` for tooling that imports the compiler API.

## Roles

Switch roles at any time from the user menu (**Switch role**) or the command palette. Actions a role cannot perform are hidden or disabled with an explanation.

| Role | Mock user | Can do |
|---|---|---|
| HR Payroll Officer | Maricel D. Santos | Manage employees and attendance, create and compute runs, add adjustments, mark runs as reviewed, generate payslips |
| Accountant | Ramon P. Villanueva | Certify or return runs, record remittance filing and payment, manage loans |
| Chief of Hospital | Dr. Elena R. Bautista | Approve (locks the run) or return runs |
| Cashier | Josefina L. Mercado | Release approved runs, generate payslips |
| System Admin | Carlo M. Reyes | Edit rates and tax tables, salary schedule versions, allowances, departments, signatories, users |

Payroll workflow: **Draft > Computed > Reviewed (HR) > Certified (Accounting) > Approved (Chief of Hospital) > Released (Cashier)**. The role that acts on a stage can return the run to an earlier stage with a required reason. Adjustments are allowed only while HR holds a Computed run. Approval locks the run.

## Demo script: a payroll run from Draft to Released

Start from fresh data (user menu, **Reset demo data**) so the names below match.

1. **Sign in as HR Payroll Officer.** The dashboard shows the Sep 1 to 30, 2026 Plantilla run in Draft, and projected totals for the period. The sidebar badge on Payroll Runs shows one run waiting on you.
2. **Optional: fix missing DTR.** Go to **Time and Attendance**. Three employees have no logs for September (Imelda M. Estrada, Nestor J. Sarmiento, Danilo F. Tiongson). Click **Import biometric logs**, choose **Use sample file**, review the validation (three rows are intentionally invalid), and import the valid rows.
3. **Open the draft run.** Payroll Runs > `REG-2026-09-PL`. The pre-computation review lists exceptions: missing DTR (if not imported), a new hire prorated from Sep 21 (Marites R. Manalo), a separation on Sep 25 (Honeylyn B. Alcantara, compulsory retirement), and an employee on leave (Maria J. Cruz).
4. **Compute payroll.** The register appears with totals. Click any row (for example Honeylyn B. Alcantara) to see the full computation breakdown: attendance used, prorated basic, PERA, longevity pay, GSIS, PhilHealth, Pag-IBIG, the tax bracket applied, loans, net pay, and government shares.
5. **Add a manual adjustment.** Click **Adjustment**, select Jerome M. Abad, choose **Step increment differential**, enter `1250.50`, and give a reason citing the NOSI. The line and the run totals recompute, and the change is logged to the audit trail.
6. **Mark as reviewed.** Tick the attestation and confirm. The stepper moves to Reviewed and shows "Awaiting Accountant".
7. **Switch role to Accountant.** Open the run from the dashboard queue. Try **Return**: return it to Computed with a reason. The run shows a "Returned by" banner. Switch back to HR, mark it reviewed again, then switch to the Accountant and **Certify**.
8. **Switch role to Chief of Hospital** and **Approve and lock**. The run is locked; adjustments and returns are no longer available.
9. **Switch role to Cashier** and **Release payroll**.
10. **Payslips.** Go to **Payslips**, pick the Sep 1 to 30 run, click **Generate payslips**, then open any payslip and **Print** (A4 layout).
11. **Follow-through.** The **Remittances** page now includes this run in the September 2026 GSIS, PhilHealth, Pag-IBIG, and BIR amounts. The **Audit Log** shows every step with before and after values.

Also worth showing: **Create payroll run** (HR) for the JO/COS group for September (it flags a JO new hire prorated from Sep 7), **Create special payroll** for September Hazard Pay, the Hazard Pay August 2026 run waiting on the Accountant, and the Subsistence and Laundry August 2026 run waiting on the Chief.

## Project structure

```
src/
  app/(auth)/login            Login
  app/(app)/...               One route segment per page (client components)
  components/ui/              shadcn/ui on Base UI
  components/data-table/      Shared DataTable on TanStack Table v9
  components/app-shell/       Sidebar, top bar, command palette, user menu
  components/<area>/          Page components per area
  lib/payroll/                Pure payroll math: money, rates, calendar, compute, engine, totals
  lib/                        Formatting, constants, permissions, workflow, selectors, reports, loans, attendance
  data/                       Deterministic seed (80 employees, 12 months of runs)
  stores/                     zustand data and session stores
  types/                      Domain types
docs/                         Assumptions and open questions
```

### Payroll engine

- All computation lives in pure, typed functions in `src/lib/payroll/compute.ts` (`computeBasicPay`, `computePera`, `computeOvertime`, `computeNightDiff`, `computeGross`, `computeGsis`, `computePhilhealth`, `computePagibig`, `computeWithholdingTax`, `computeLoanDeductions`, `computeNet`, `computePayrollLine`, `computeSpecialLine`, and more).
- Every rate, ceiling, and tax bracket comes from `src/lib/payroll/rates.ts` as versioned `RatesConfig` objects. The engine uses the version in force on the period start (`ratesForDate`). Admins publish new versions in Settings.
- Money is integer centavos. Anything involving a rate or division goes through decimal.js with half-up rounding. Payroll is monthly: salary, PERA, allowances, contributions, and loan amortizations are taken in full each month and prorated only for days not in service.
- Tests in `src/lib/payroll/__tests__/` cover each function, including contribution floors and ceilings, the zero-tax bracket, bracket continuity, partial months for new hires and separations, JO/COS rules, loans, adjustments, and the net pay floor flag.
